# Validation scope

Validated locally on 2026-11-18. Binding version: 1.0.0. Embedded native SDK
version: 2.1.1, built from the accompanying client checkout.

## Passed in real Unity

Unity 6.3 LTS (6000.3.28f1), Apple Silicon, licensed Unity Personal:

- Actual UPM tarball import and Editor play mode. Unsupported Editor
  initialization is explicit; no simulated readiness or accepted events.
- Android 15 / API 35 ARM64 emulator: real IL2CPP player, High managed stripping,
  Release minification. C# → JNI callbacks, identity, configuration, Unicode,
  standard/custom events, OAID, Rust strategy execution, DDA operations,
  explicit session switching, foreground clock advancement, automatic
  background `session_end`, and same-session reporting after resuming passed.
- iOS 27 ARM64 simulator: Unity export/postprocessor, Xcode Release build,
  embedded frameworks, IL2CPP C ABI/PInvoke callbacks, configuration, Unicode,
  events, CAID, Rust execution, DDA operations and foreground clock passed.
  Background ends arrived without relying on Unity frames. XCTest activated
  the same running app; subsequent probe events retained the same session and
  no new config request was made. Background intervals were excluded by the
  native accumulated clock.
- All SDK requests in these tests went to a localhost HTTP fixture. Test-only
  HTTP permissions and probe heartbeats are confined to disposable projects;
  the SDK does not add heartbeats or change production network security.

Evidence generated by `Tools~/test_player.py` is under
`build/player-validation/<android|ios>/`: `sdk-result.json`,
`sdk-receipts.json`, `sdk-runtime.log`, build logs and the iOS XCTest result.

## Package and player sizes

Decimal MB. Empty probe hosts use the same build settings; the SDK host also
runs integration checks. Measurements include JSON/IL2CPP code and all native
dependencies. The package budget is less than 1,000,000 additional compressed
bytes per platform. The test tool fails if a requested byte budget is exceeded.

| Artifact | Baseline | With SDK | Difference |
| --- | ---: | ---: | ---: |
| Android ARM64 Release APK | 10.67 MB | 11.43 MB | **0.763 MB** |
| iOS ARM64 device Release IPA payload, unsigned | 8.80 MB | 9.78 MB | **0.976 MB** |

Exact compressed increments are **763,211 bytes** on Android and **975,545 bytes**
on iOS. Both are below the 1,000,000-byte budget in these matching builds. iOS
exports only the five Unity C ABI functions, strips non-global symbols and uses
Swift `-Osize`. This changes native packaging/compiler settings, not native SDK
event, lifecycle, identity, queue, clock or retry behavior. Archive dSYMs remain
available separately for native diagnostics.

The old mandatory Newtonsoft wrapper added 5.91 MB to the Android APK. A
separate JSON-only control added 5.26 MB, identifying the heavy dependency as
the primary cause. Removing just generic object conversion saved only 1.3 KB.
The replacement uses small SDK JSON nodes with no arbitrary-object reflection.
The new Android increment includes 0.59 MB of compressed Rust runtime, about
0.12 MB of additional IL2CPP code and 0.017 MB of additional metadata; native
Java/JNI and probe/engine differences account for the remainder.

The simulator app includes simulator linking symbols and framework slices. Its
raw difference is **not** a device IPA or App Store download-size measurement.
The separate `ios-device` fixture compares unsigned ARM64 Release
device apps in ZIP-compressed IPA payloads. No physical device or App Store
processed download is measured by that comparison.

Repeat the size comparison with a game's actual release settings before
publishing. The fixture uses Unity 6.3 IL2CPP with High managed stripping;
changing Unity version, stripping, target architectures or enabled SDK APIs can
change the increment. Signing, encryption and App Store processing are outside
the unsigned IPA measurement.

The UPM tarball contains Android ARMv7/ARM64/x86_64 native libraries plus iOS
device/simulator libraries. Removing an unused macOS runtime slice reduced the
download from 5.43 MB to approximately 4.40 MB. Only target platform/architecture
artifacts are selected for a player.

## Native/managed regressions

- C# compiler/protocol harness: Editor, Android and iOS branches, 64 assertions.
  Covers payload copies, native-owned readiness/timeouts, main-thread dispatch
  through Unity's synchronization context, and no extra telemetry quota.
- Dependency-free JSON parser: 6,423 assertions per managed branch, including
  1,500 randomized documents checked against the independent .NET JSON parser
  used only by the test harness. Includes Unicode/escapes, signed/unsigned
  64-bit boundaries, numbers beyond 2^53, null/missing fields, malformed input,
  locale independence, overflow, nesting/cycle protection and clone isolation.
- Android native JVM smoke suite and JSON integer regression. Integer parsing
  preserves 64-bit handles; JNI encodes tagged handles as signed Java longs
  without changing their bits.
- Rust runtime: 10 library tests, including tagged JNI handle round trips.
- Swift bridge: 3 tests with isolated storage and mock HTTP, including native
  refresh/TTL behavior and same-session no-op semantics.
- Real Android Activity bridge probe additionally checks same-session no-op,
  forced/default config refresh, native lifecycle and Rust execution.

## Remaining scope

Physical devices, minimum supported OS releases, other Unity Editor versions,
production game registration/ingress, and ad-provider callback integrations
have not been tested. No production telemetry or remote configuration was
written. Unity mobile players need a registered game's client key with
`IsDebug=true` for a live service validation.
